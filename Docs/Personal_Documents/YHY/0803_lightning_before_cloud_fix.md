# 번개가 먹구름보다 먼저 치는 버그 수정 (0803)

## 증상
"먹구름이 이동해서 번개가 쳐야 하는데, **번개가 먼저 치고 먹구름이 그쪽으로 이동**한다."
→ 섬광이 구름의 진한 부분이 아니라 그 **앞쪽 빈 곳**에 번쩍이고, 이후 먹구름이 그리로 다가옴.

## 원인 (실측으로 확정)
`LightningSystem.OnWeatherStep`의 **대상 셀 선정 방식** 문제.

1. 예전 로직: 그리드 전 셀을 훑어 `RainIntensityAt(cell) >= 0.4`인 셀을 **모두** 후보에 넣고 **균등 랜덤**으로 하나 선택.
2. `RainIntensityAt`의 판정 반경 `r = scale*0.9`(≈ 구름 스프라이트 폭 전체)라, 먹구름 하나가 **여러 셀(실측 7셀)** 을 덮음.
3. 그 7셀 중엔 구름 중심보다 **앞쪽 가장자리** 셀도 포함 → 균등 추첨이 그걸 자주 뽑음.

### 실측 데이터 (수정 전)
먹구름 1개(m=0.81, scale=1.03, 반경 0.93u)가 셀 (0,22)~(2,23) 7개를 덮음:
| 셀 | 구름중심과의 거리 | leadDot(바람 진행방향 정렬) |
|---|---|---|
| (0,22) | 0.59u | **+1.00 (정면 앞쪽)** |
| (0,23) | 0.69u | +0.52 |
| (2,23) | 0.85u | -0.99 (뒤쪽) |

`leadDot = +1.00`이면 그 셀은 구름이 **가고 있는 방향의 정면 가장자리**.
거기에 섬광 + (가연지형이면) 불→저기압이 생기면, 저기압이 구름을 그쪽으로 당김
→ **"번개 먼저, 먹구름이 뒤따라 이동"** 처럼 보임. 사용자 관찰과 정확히 일치.

## 수정
번개를 **먹구름의 '중심'(진한 부분)에만** 치도록 변경.

- `MinimapClouds.CollectStormCenters(List<Vector3>, minIntensity)` 신규:
  먹구름(수분≥문턱)이고 세기(수분×크기)≥문턱인 구름들의 **중심 월드좌표**만 수집.
- `LightningSystem.OnWeatherStep`:
  전 셀 스캔·균등추첨 대신 → 먹구름 중심 하나를 결정론 랜덤으로 고르고,
  그 중심이 있는 셀(`grid.WorldToCell`)에 번개. 섬광이 구름 위에 정확히 떨어짐.

### 검증 (수정 후, live)
- 섬광↔구름중심 오프셋: **최대 0.35u**(반 칸 이내). (예전 최대 0.86u 앞쪽가장자리)
- **결정론 유지**: ProjectForward 2회 동일(stepSum=829500, rainSum=37.0776). 라이브 상태 완전 복원(clouds 30→30, simStep 1082 그대로, IsProjecting=False).
- 컴파일·런타임 에러 0.

## 부수 효과 (의도된 개선)
불의 저기압이 구름의 **자기 중심**을 당기므로, 구름이 진행방향으로 튀지 않고
제자리에서 뭉쳐 비로 해소됨 → 날씨 흐름이 더 자연스러움.
